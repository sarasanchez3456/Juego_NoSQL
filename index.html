Comparativa SQL vs NoSQL - seis dimensiones clave
AspectoSQL / relacionalNoSQL / no relacional
Modelo de datosRELACIONAL
Datos organizados en tablas con filas, columnas y relaciones explícitas mediante claves primarias y foráneas.		VARIOS MODELOS
Documentos (JSON/BSON), clave-valor, columnas anchas (wide-column), grafos, según el motor utilizado.
Esquema rígido vs. flexibleRÍGIDO
Esquema predefinido con tipos de datos, restricciones y validaciones. Requiere migraciones para cambios estructurales.		FLEXIBLE
Esquema dinámico o "schema-less". Permite documentos con estructuras diferentes y evolución ágil de los datos.
Escalabilidad vertical vs. horizontalVERTICAL
Escala aumentando recursos (CPU, RAM, disco) de un único servidor. Más costoso en límites altos.		HORIZONTAL
Escala añadiendo más nodos al cluster. Reparte datos y carga, ideal para grandes volúmenes y alta demanda.
ACID vs. BASEACID
Garantiza Atomicidad, Consistencia, Aislamiento y Durabilidad. Prioriza la integridad de datos sobre disponibilidad.		BASE
Prioriza Básicamente Disponible, Estado Suave (Soft state), Consistencia Eventual. Favorece disponibilidad y particionamiento. Muchos motores modernos también ofrecen transacciones ACID.
Lenguaje de consultaSQL
Structured Query Language, declarativo y ampliamente estandarizado con dialectos (PostgreSQL, MySQL, SQL Server).		VARIADO
Depende del motor: APIs específicas, lenguajes propios (Cypher para Neo4j), o consultas tipo SQL (MongoDB Query API, CQL para Cassandra).
Casos de uso y motoresRELACIONAL
Finanzas, contabilidad, ERP, CRM, inventarios. Motores: PostgreSQL, MySQL, MariaDB, Microsoft SQL Server, Oracle.		NO RELACIONAL
Catálogos, redes sociales, IoT, caché, análisis en tiempo real, grafos. Motores: MongoDB, Redis, Cassandra, CouchDB, Neo4j, DynamoDB.

Nota: son tendencias generales, no fronteras absolutas. La elección depende del patrón de acceso, la consistencia, la escala y las capacidades concretas del motor.
